Triggering is handled by IntersectionObserver watching each .stat card — no scroll listener, no manual getBoundingClientRect math on every frame. Once a card crosses the threshold it unobserves itself, so the count only ever plays once per page load, and each card's requestAnimationFrame loop runs independently against its own start timestamp so the four counters don't drift relative to each other even if they start at slightly different scroll moments.

The easing itself is plain math, not a library: 1 - Math.pow(2, -10 * progress) for easeOutExpo. Feeding raw scroll progress into a linear interpolation reads as mechanical; running the same 0→1 progress through an easing function before multiplying by the target value is what makes a UI counter feel like a purposeful animation instead of a odometer stepping through numbers.
