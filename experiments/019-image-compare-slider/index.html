Before/after compare slider

A single <input type="range">, made invisible and stretched over the whole image, drives one CSS custom property (--pos). Everything else - the clip-path on the "before" layer, the divider line, the round handle - just reads that variable, so there's exactly one piece of JavaScript state and zero manual style writes per frame.

Using the native range input for the drag interaction (rather than hand-rolling pointer-move math) means keyboard support, touch support, and accessible focus styling all come for free - arrow keys nudge the slider by 1%, Home/End jump to the edges, and screen readers announce it as a slider with its current value.
