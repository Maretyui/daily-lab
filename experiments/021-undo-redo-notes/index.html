Undo/redo notes board

Drag notes around, edit their text, add new ones, delete old ones - every one of those actions pushes a fresh snapshot onto a history stack, taken with structuredClone() rather than a shared reference. That distinction actually matters here: storing notes itself in the history array would mean every "snapshot" is secretly the same live object - moving a note later would silently rewrite every past entry too, and undo would do nothing. A real deep clone per commit is what makes travelling backwards in time actually work.

Commits only happen at meaningful boundaries - finishing a drag (pointerup), finishing an edit (blur), or clicking add/delete - not on every pointermove or keystroke. That's the same coalescing real editors do: one undo step per intent, not one per pixel or character. Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z (or Ctrl+Y) work anywhere on the page outside of a note's own text.
